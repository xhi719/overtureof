# 복합 직업 분류의 검색 명칭

`occupation-components.json`은 공식 분류의 한 코드가 복수 직업명을 포함하고 그 구성에 별도 공식 코드가 없는 경우, 원문을 검토해 검색에 표시할 명칭을 기록합니다. 개별 명칭에는 **새 공식 코드나 별도 예측이 없으며**, 해당 공식 직업군의 값과 시각을 공유합니다. 공식 원문, 코드 및 원래의 직접 상세 주소는 보존합니다. 의미가 불확실하거나 명칭이 단순 동의어인 경우 임의로 분해하지 않습니다. 단순 동의어 그룹은 검토된 한 가지 표시명만 등록할 수 있습니다.

`npx tsx scripts/sync-occupation-components.ts`는 명세에 적힌 시스템·버전·코드와 DB의 부모 직업을 확인한 후 승인된 한국어·영어 명칭을 `occupation_aliases`에 추가합니다. 이미 존재하는 별칭은 덮어쓰지 않으며 삭제하지도 않습니다. 각 표시명은 DB의 해당 부모·언어·승인된 철자와 일치하는 별칭이 있을 때만 사용합니다. 직접 상세 주소에는 승인된 ID를 붙이며, ID가 없거나 다른 직업에 속하거나 DB 별칭이 없으면 받아들이지 않습니다.

재적재 시에는 KSCO·O*NET 직업 분류와 번역을 먼저 가져온 뒤 동기화 스크립트를 실행합니다. 명세에 있는 부모가 하나라도 DB에 없으면 스크립트는 오류를 내고 트랜잭션 전체를 취소하므로 별칭을 일부만 추가하지 않습니다. 의도적으로 제외된 직업이라면 공식 원본·제외 사유를 검토하여 명세에서 해당 구성명을 제거한 후 다시 실행합니다. 누락을 해결한다는 이유로 제외된 직업을 자동으로 복원하지 않습니다. 나중에 명세에서 빠진 명칭도 기존 별칭 테이블에서는 자동 삭제하지 않지만, 승인된 명세 ID가 없으면 분리된 직업 표시로는 노출하지 않습니다.

관리자가 기존 별칭을 변경·삭제하면 등록 명세와 더 이상 일치하지 않아 구성명이 표시되지 않을 수 있습니다. 변경은 원문 확인 및 검토 후 명세를 갱신하고 동기화 스크립트를 다시 실행해야 합니다. 지원하지 않는 언어는 한국어 이름으로 대체하며, 새 번역을 자동으로 생성하지 않습니다. 기존 DB를 수정하기 전에는 백업을 권장합니다.

한국표준직업분류 상위 항목은 명칭 구성 요소별 공식 하위 코드가 확인될 때에만 검색에서 그 하위 코드를 우선합니다. 같은 표시명은 검색 결과에서 하나로 보일 수 있으나, 이는 서로 다른 분류체계 직업의 공식 대응을 뜻하지 않습니다. `hidden-search-occupations.json`에는 공식 원문이 여러 직무를 포괄해 각각 식별하기 어려워 검색에서 숨긴 특정 항목을 기록하며, 그 공식 기록과 직접 주소를 삭제하지 않습니다.
