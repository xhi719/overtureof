# OpenAI: GPTs are GPTs, occupation-level research scores

Source: [OpenAI research announcement](https://openai.com/index/gpts-are-gpts/), March 17, 2023; [original data and definitions](https://github.com/openai/GPTs-are-GPTs). The repository is MIT licensed; the original license is preserved in this directory. Original data CSV SHA-256: `40c74f53de40aec91c0017d80690cbba915f83a8bb414bcf2f884692f1749acb`.

This study scores potential *task exposure* to LLM capabilities using human and GPT-4 raters. The fields `_alpha`, `_beta`, and `_gamma` are distinct exposure measures defined by the authors. They are not employment-displacement probabilities, observed adoption rates, individual risks, or dates. These scores must not be represented as an empirical displacement forecast. With the user’s explicit approval, this project uses them as one input to a separately labeled, unvalidated hypothetical model; the study does not support or validate that model.

The original table has 923 occupations. All 923 codes and official English titles match the original O*NET-SOC 31.0 source records. After 414 occupation records were excluded due to translation quality, 540 of these matches remain in the local database. The importer stores all six unmodified numeric exposure fields for each remaining matched occupation, preserving the raw number text as provenance, and associates them with a research source; it creates no validated forecasts. The source was locally reviewed and approved for task-exposure use only; a new database import starts pending. No occupational crosswalk, estimate, translation, or interpretation is invented. The source dataset has no values for the other 93 O*NET source occupations or KSCO occupations; excluded occupations are not imported.

Run `python etl/normalize_openai_exposure.py` to verify the original checksum, record count, and value ranges. Run `npx tsx scripts/import-openai-exposure.ts` to check exact O*NET code/title matches and idempotently import into an initialized local database. A pending research source must be reviewed before it is made public. The current local database has the source approved; an empty database created by the importer needs its own review and approval. Source-level scientific review is separate from the checks made by the importer.
